# ToroPass Issuer API Reference

This reference documents the live backend behavior in `backend/toropass_issuer`.

Base URL:

```text
http://<host>:<port>/api/v1
```

Global notes:

- JSON request and response bodies
- Validation pipe is enabled with `whitelist: true`
- Rate limit is 10 requests per 60 seconds per IP
- Most protected endpoints also require `x-api-key`
- Health check lives at `/`, outside the versioned API

For auth headers, see [AUTHENTICATION.md](./AUTHENTICATION.md).

## Response Shape

Most successful responses follow one of these forms:

```json
{
  "status": "success",
  "message": "Optional message",
  "data": {}
}
```

or

```json
{
  "status": "success",
  "message": "Optional message"
}
```

Error bodies are generated by NestJS exceptions and may vary by exception type.

## Health

### `GET /`

Checks:

- PostgreSQL connectivity
- Toronet connectivity via `checkTnsAvailability('admin')`

Success response:

```json
{
  "status": "success",
  "message": "ToroPass Issuer Server is live 🚀",
  "timestamp": "2026-06-06T12:00:00.000Z",
  "dependencies": {
    "database": "UP",
    "toronet": "UP"
  }
}
```

Failure behavior:

- Returns HTTP `503` with dependency status payload

## Wallet Endpoints

### `GET /api/v1/wallets/tns?username=<username>`

Auth:

- `x-api-key`
- HMAC headers
- HMAC headers

Purpose:

- Check whether a TNS username is available on Toronet

Query params:

- `username`: required string

Success response:

```json
{
  "status": "success",
  "data": {
    "username": "alice",
    "isAvailable": true,
    "message": "Username is available!"
  }
}
```

### `POST /api/v1/wallets/create`

Auth:

- `x-api-key`
- HMAC headers

Purpose:

- Create a brand-new Toronet wallet and claim the TNS name
- Create a local ToroPass user
- Issue first-party wallet JWTs

Body:

```json
{
  "username": "alice",
  "password": "strong-password"
}
```

Validation:

- `username`: required string
- `password`: required string

Success response:

```json
{
  "status": "success",
  "message": "Toronet wallet and TNS name claimed successfully.",
  "data": {
    "username": "alice",
    "address": "0x123...",
    "tnsName": "alice",
    "tokens": {
      "accessToken": "eyJ...",
      "refreshToken": "eyJ..."
    }
  }
}
```

Important behavior:

- Fails if the username is already taken on Toronet
- Creates a local user with placeholder KYC values until KYC is completed

### `POST /api/v1/wallets/validate`

Auth:

- `x-api-key`
- HMAC headers

Purpose:

- Validate an existing Toronet wallet using username and password
- Link it to a local ToroPass user if needed
- Issue first-party wallet JWTs

Body:

```json
{
  "username": "alice",
  "password": "wallet-password"
}
```

Success response:

```json
{
  "status": "success",
  "message": "Wallet validated successfully.",
  "data": {
    "username": "alice",
    "address": "0x123...",
    "tnsName": "alice",
    "tokens": {
      "accessToken": "eyJ...",
      "refreshToken": "eyJ..."
    }
  }
}
```

Important behavior:

- Resolves the TNS name to an address first
- If wallet exists locally, password is checked against the local hash
- If wallet does not exist locally, password is verified against Toronet and a local user is created
- Returns `401` for invalid wallet passwords

### `GET /api/v1/wallets`

Auth:

- `x-api-key`
- wallet `Authorization` bearer token
- HMAC headers

Purpose:

- Fetch the active wallet profile for the current first-party user

Success response:

```json
{
  "status": "success",
  "message": "Wallet retrieved successfully.",
  "data": {
    "id": "user-uuid",
    "kycVerified": false,
    "kycAnchorHash": null,
    "wallet": {
      "address": "0x123...",
      "tnsName": "alice",
      "network": "<active-network>"
    }
  }
}
```

Important behavior:

- `wallet.network` reflects the active Toronet SDK network selected by `TORONET_NETWORK`

### `POST /api/v1/wallets/change-password`

Auth:

- `x-api-key`
- wallet `Authorization` bearer token
- HMAC headers

Purpose:

- Change the current user wallet password both on Toronet and in local storage

Body:

```json
{
  "oldPassword": "old-password",
  "newPassword": "new-password"
}
```

Validation:

- `oldPassword`: required string
- `newPassword`: required string, minimum length `6`

Success response:

```json
{
  "status": "success",
  "message": "Password changed successfully."
}
```

### `POST /api/v1/wallets/refresh`

Auth:

- `x-api-key`

Purpose:

- Exchange a refresh token for a new wallet access/refresh token pair

Body:

```json
{
  "refreshToken": "eyJ..."
}
```

Success response:

```json
{
  "status": "success",
  "message": "Session refreshed successfully.",
  "data": {
    "accessToken": "eyJ...",
    "refreshToken": "eyJ..."
  }
}
```

Important behavior:

- Current session record is deleted after refresh
- Invalid, expired, or revoked refresh tokens return `401`

## KYC Endpoint

### `POST /api/v1/kyc/verify`

Auth:

- `x-api-key`
- wallet `Authorization` bearer token
- HMAC headers

Purpose:

- Verify user KYC data with Toronet and persist verified state locally

Body:

```json
{
  "firstName": "Ada",
  "middleName": "N",
  "lastName": "Toro",
  "bvn": "12345678901",
  "currency": "NGN",
  "phoneNumber": "08000000000",
  "dob": "1990-05-20",
  "address": "0x123..."
}
```

Success response:

```json
{
  "status": "success",
  "data": {
    "success": true,
    "message": "Identity verified and securely anchored to the Toronet blockchain."
  }
}
```

Important behavior:

- Wallet address must already exist locally
- Re-verifying an already verified user is rejected
- `bvn` is stored as a SHA-256 hash, not in plaintext
- `dob` is stored as a `Date`

## OAuth Developer App Endpoints

### `POST /api/v1/oauth/apps/register`

Auth:

- `x-api-key`
- wallet `Authorization` bearer token
- HMAC headers

Purpose:

- Register a new third-party app under the current ToroPass user

Body:

```json
{
  "name": "DeFi Swap Platform",
  "redirectUri": "https://example.com/callback"
}
```

Validation:

- `name`: required string
- `redirectUri`: required valid URL

Success response:

```json
{
  "status": "success",
  "message": "Application credentials generated successfully. Save the client secret safely!",
  "data": {
    "id": "app-uuid",
    "name": "DeFi Swap Platform",
    "clientId": "toro_client_...",
    "clientSecret": "toro_sk_...",
    "redirectUri": "https://example.com/callback"
  }
}
```

Important behavior:

- `clientSecret` is only returned once in plaintext
- Stored secret is hashed in the database

### `GET /api/v1/oauth/apps`

Auth:

- `x-api-key`
- wallet `Authorization` bearer token
- HMAC headers

Purpose:

- List all apps registered by the current developer user

Success response:

```json
{
  "status": "success",
  "data": [
    {
      "id": "app-uuid",
      "name": "DeFi Swap Platform",
      "clientId": "toro_client_...",
      "redirectUri": "https://example.com/callback",
      "isActive": true,
      "createdAt": "2026-05-28T08:48:19.757Z"
    }
  ]
}
```

### `DELETE /api/v1/oauth/apps/:appId`

Auth:

- `x-api-key`
- wallet `Authorization` bearer token
- HMAC headers

Purpose:

- Delete a registered app owned by the current user

Success response:

```json
{
  "success": true,
  "message": "Application successfully deleted."
}
```

## OAuth User Consent Flow

### `POST /api/v1/oauth/authorize`

Auth:

- `x-api-key`
- wallet `Authorization` bearer token
- HMAC headers

Purpose:

- Save or update consent for the current user and issue a short-lived authorization code

Body:

```json
{
  "client_id": "toro_client_...",
  "redirect_uri": "https://example.com/callback",
  "scopes": ["kyc_status", "wallet"]
}
```

Success response:

```json
{
  "status": "success",
  "data": {
    "code": "hex-authorization-code"
  }
}
```

Important behavior:

- Validates client existence and active status
- Validates exact redirect URI match
- Upserts consent for `30` days
- Issues authorization code valid for `5` minutes

### `POST /api/v1/oauth/token`

Auth:

- none at route level

Purpose:

- Exchange an authorization code for an app access token and profile payload

Body:

```json
{
  "client_id": "toro_client_...",
  "code": "hex-authorization-code",
  "redirect_uri": "https://example.com/callback",
  "client_secret": "toro_sk_optional_for_server_flow"
}
```

Success response:

```json
{
  "status": "success",
  "data": {
    "accessToken": "toro_tk_...",
    "profile": {
      "id": "user-uuid",
      "kycVerified": true,
      "kycAnchorHash": null,
      "wallet": {
        "address": "0x123...",
        "tnsName": "alice",
        "network": "<active-network>"
      }
    }
  }
}
```

Important behavior:

- `client_secret` is optional at the controller level
- If provided, it must match the stored hash
- Authorization code is burned after successful exchange
- App token lifetime is `30` days

### `GET /api/v1/oauth/profile`

Auth:

- `Authorization: Bearer <oauth_access_token>`

Purpose:

- Fetch profile data silently using an app-scoped OAuth token

Success response:

```json
{
  "status": "success",
  "data": {
    "id": "user-uuid",
    "kycVerified": true,
    "kycAnchorHash": null,
    "wallet": {
      "address": "0x123...",
      "tnsName": "alice",
      "network": "<active-network>"
    }
  }
}
```

Important behavior:

- Revoked consent causes the stored token to be deleted and request to fail
- Expired app tokens return `401`

## Consent Management Endpoints

Note:

- The current controller path is spelled `conscents` in code. The routes below intentionally match the live implementation.

### `GET /api/v1/conscents/:userId`

Auth:

- `x-api-key`
- wallet `Authorization` bearer token
- HMAC headers

Purpose:

- List active app consents for a user

Success response:

```json
{
  "status": "success",
  "data": [
    {
      "appId": "app-uuid",
      "appName": "DeFi Swap Platform",
      "scopes": ["kyc_status", "wallet"],
      "grantedAt": "2026-05-28T08:48:19.757Z",
      "expiresAt": "2026-06-27T08:48:19.757Z"
    }
  ]
}
```

Important behavior:

- Expired consents are filtered out before response
- The live route still includes `:userId`, but the controller now uses the authenticated wallet user from the bearer token

### `DELETE /api/v1/conscents/:userId/:appId`

Auth:

- `x-api-key`
- wallet `Authorization` bearer token
- HMAC headers

Purpose:

- Revoke one app's access for a user

Success response:

```json
{
  "status": "success",
  "message": "Access revoked successfully."
}
```

Important behavior:

- The live route still includes `:userId`, but revocation is performed for the authenticated wallet user from the bearer token

## Suggested Wallet-App Integration Order

If you are integrating the Flutter wallet next, these backend routes are the likely order of use:

1. `GET /api/v1/wallets/tns`
2. `POST /api/v1/wallets/create` or `POST /api/v1/wallets/validate`
3. `GET /api/v1/wallets`
4. `POST /api/v1/kyc/verify`
5. `GET /api/v1/conscents/:userId`
6. `DELETE /api/v1/conscents/:userId/:appId`
7. OAuth developer flows as needed
