# ToroPass Issuer Communication Examples

These examples reflect the live backend behavior in `backend/toropass_issuer`.

Base URL:

```text
http://localhost:3000/api/v1
```

## Shared Header Placeholders

Protected first-party routes usually need some combination of:

```text
x-api-key: your_super_secret_flutter_api_key_here
Authorization: Bearer your_wallet_access_token_here
x-device-id: emulator-5554
x-timestamp: <unix-seconds>
x-signature: <hmac_sha256_hex_of_timestamp:deviceId>
```

See `backend/toropass_issuer/AUTHENTICATION.md` for the exact rules.

## Step 1: Register a Developer App

This route requires:

- `x-api-key`
- wallet bearer token
- HMAC headers

```bash
curl -X POST http://localhost:3000/api/v1/oauth/apps/register \
  -H "Content-Type: application/json" \
  -H "x-api-key: your_super_secret_flutter_api_key_here" \
  -H "Authorization: Bearer your_wallet_access_token_here" \
  -H "x-device-id: emulator-5554" \
  -H "x-timestamp: 1780732800" \
  -H "x-signature: your_hmac_signature_here" \
  -d '{
    "name": "DeFi Swap Platform",
    "redirectUri": "https://example.com/callback"
  }'
```

Response:

```json
{
  "status": "success",
  "message": "Application credentials generated successfully. Save the client secret safely!",
  "data": {
    "id": "app-uuid",
    "name": "DeFi Swap Platform",
    "clientId": "toro_client_xxxxx",
    "clientSecret": "toro_sk_xxxxx",
    "redirectUri": "https://example.com/callback"
  }
}
```

## Step 2: Simulate User Consent Inside ToroPass Wallet

This route requires:

- `x-api-key`
- wallet bearer token
- HMAC headers

```bash
curl -X POST http://localhost:3000/api/v1/oauth/authorize \
  -H "Content-Type: application/json" \
  -H "x-api-key: your_super_secret_flutter_api_key_here" \
  -H "Authorization: Bearer your_wallet_access_token_here" \
  -H "x-device-id: emulator-5554" \
  -H "x-timestamp: 1780732800" \
  -H "x-signature: your_hmac_signature_here" \
  -d '{
    "client_id": "toro_client_xxxxx",
    "redirect_uri": "https://example.com/callback",
    "scopes": ["kyc_status", "wallet"]
  }'
```

Response:

```json
{
  "status": "success",
  "data": {
    "code": "authorization-code"
  }
}
```

## Step 3: Exchange the Authorization Code

This route is public at the controller level. Server-side consumers can also provide `client_secret`.

```bash
curl -X POST http://localhost:3000/api/v1/oauth/token \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "toro_client_xxxxx",
    "code": "authorization-code",
    "redirect_uri": "https://example.com/callback",
    "client_secret": "toro_sk_xxxxx"
  }'
```

Response:

```json
{
  "status": "success",
  "data": {
    "accessToken": "toro_tk_xxxxx",
    "profile": {
      "id": "user-uuid",
      "kycVerified": false,
      "kycAnchorHash": null,
      "wallet": {
        "address": "0x123...",
        "tnsName": "alice",
        "network": "<active-network>"
      }
    }
  }
}
```

## Step 4: Fetch the Profile Silently

This route uses the OAuth access token returned in step 3.

```bash
curl -X GET http://localhost:3000/api/v1/oauth/profile \
  -H "Authorization: Bearer toro_tk_xxxxx"
```

Response:

```json
{
  "status": "success",
  "data": {
    "id": "user-uuid",
    "kycVerified": false,
    "kycAnchorHash": null,
    "wallet": {
      "address": "0x123...",
      "tnsName": "alice",
      "network": "<active-network>"

}
```

- HMAC headers
